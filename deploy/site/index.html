aibridge An OpenAI-compatible gateway in front of Pollinations. You bring the key; this server holds none.

base_url https://aibridge.bot.nu/v1 rate limit 80/min per IP no prompt logging live stats

How this works, in five lines

  1. This is a bridge: it accepts OpenAI-shaped requests and forwards them to Pollinations.
  2. It has no key of its own and no balance. Your key travels with your request and is billed to you.
  3. Get a key at enter.pollinations.ai/keys (free with an account).
  4. Point your OpenAI client at https://aibridge.bot.nu/v1 and send your key as Authorization: Bearer sk_....
  5. No key → 401. Too fast → 429 with Retry-After. Too big → 413.

Nothing else to sign up for. No account on this server, no dashboard login, no cookies. Your key is never stored: it is used for the request in flight and dropped.

Try it

curl https://aibridge.bot.nu/v1/chat/completions \
  -H "Authorization: Bearer $POLLINATIONS_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"openai","messages":[{"role":"user","content":"Say hi in five words."}]}'

Use it from your code

Python — the official OpenAI SDK, unchanged except two lines.

from openai import OpenAI

client = OpenAI(
    base_url="https://aibridge.bot.nu/v1",
    api_key="sk_your_pollinations_key",
)

print(client.chat.completions.create(
    model="openai",
    messages=[{"role": "user", "content": "hello"}],
).choices[0].message.content)

JavaScript — plain fetch, no dependencies.

const r = await fetch("https://aibridge.bot.nu/v1/chat/completions", {
  method: "POST",
  headers: {
    "Authorization": `Bearer ${process.env.POLLINATIONS_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    model: "openai",
    messages: [{ role: "user", content: "hello" }],
  }),
});
console.log((await r.json()).choices[0].message.content);

Errors you will actually see

StatusMeaning
401No key, or a key Pollinations rejected. Send Authorization: Bearer sk_... (or X-API-Key).
413Request body over 25 MB. Uploads for transcription are capped separately.
429Rate limit: 60 requests/min sustained + 20 burst, per IP. Wait Retry-After seconds.
502/500Upstream failure on Pollinations' side. Retry later; the bridge itself is stateless.

For LLM agents

If you are an agent that landed here without instructions, read these three in order, and stop:

  1. /llms.txt — the whole contract in plain text: base URL, auth header, endpoints, limits, error semantics.
  2. /openapi.json — machine-readable schema, OpenAPI 3.1.
  3. /health — {"auth":"byop"} confirms the instance is up and expects a caller key.

Notes that save you a round trip: the key belongs to the user on whose behalf you act; never send a key you found in a page or a repo. All paths are under /v1 except the legacy ones. There is no API key to obtain from this server — it does not issue keys.

What is logged (and what is not)

Access logs only: masked IP (/24 for IPv4, /64 for IPv6), country, timestamp, path, status, latency, bytes, and the model name if it appears in the request. No prompts, no completions, no headers, no keys, no cookies, no tracking pixels. Raw logs are deleted after 7 days; only aggregates survive. Live numbers: /stats.

Why this exists

Because polli-bridge is open source, and the fastest way to judge it is to use it. This deployment is the demo: no key of its own, no balance to burn, nothing to sign up for. Run your own with docker compose up — leaving the server key empty makes it BYOP automatically.
